## Initial Feasibility Study ##

The system can be developed using the technologies, tools, and technical skills available to the team. The project could be completed using HTML, CSS, JavaScript, and Java. However, we would prefer to use more organized and efficient frameworks, such as Angular and ASP.NET, as they would make the development process more structured and straightforward. One drawback is that not everyone in the group is familiar with Angular or ASP.NET, meaning that some team members would need to learn these technologies before using them effectively. If this becomes a significant limitation, the system can still be developed using more familiar technologies such as HTML, CSS, JavaScript, and Java. Overall, the project is technically feasible with the resources and skills available to the team.

In terms of economic feasibility, we believe the initial cost of the project will be practically zero, as the system can be developed and hosted using computers already available to the group. No significant additional hardware or software would be required during development. However, if the project advances to the point where it is deployed and used in the real world, a limitation would be the hosting capacity of the group's computers as the number of users increases. In that case, the system would need to be moved to a dedicated server or a more powerful computer, which could introduce additional hosting and infrastructure costs.

The project addresses a genuine problem faced by senior design students who may not know how or when to select an advisor. Currently, students may rely on sending emails or visiting professors' offices, which can be inconvenient and inefficient. Students cannot easily determine whether a professor is already fully booked, and visiting an office can be a gamble since they may not know where the office is, when the professor will be available, or whether the entire team can meet at that time. This can make the advisor selection process more difficult than necessary.

The proposed system would provide students with a more convenient way to find available advisors, view their areas of expertise, and communicate with them. Overall, we believe the system could genuinely improve the senior design advisor selection process and that the intended users are likely to accept it because it provides a more organized and convenient alternative to the current process.

The project can realistically be completed within the available course duration, although this will depend on the group's ability to meet regularly and make decisions regarding the system's design and development. If the group can agree on meeting times and reach a consensus when problems or disagreements arise, the project should be achievable within the given timeframe. The main challenge will be balancing the project with other university responsibilities, particularly assignments and exams, which could slow down progress if not managed properly.

Overall, we believe that the proposed project is feasible within the available course duration and resources. The system can be developed using technologies and hardware already available to the team, and it requires little to no initial financial investment. More importantly, the project addresses a genuine problem and could provide a practical improvement to the current senior design advisor selection process. The main constraints are the team's varying technical knowledge, particularly with frameworks such as Angular and ASP.NET, as well as the group's availability due to other academic responsibilities. If the team manages its time effectively, communicates regularly, and adapts its technology choices to its available skills, the project should be successfully completed.
