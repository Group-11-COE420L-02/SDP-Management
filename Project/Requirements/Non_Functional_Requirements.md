# Non-Functional Requirements #

## Mahmoud Contributions ##
### NFR-01 ###
Category: Performance
Non-Functional Requirement: The system shall display professor search and filtering results within 3 seconds under normal operating conditions.
Contributor: Mahmoud

### NFR-02 ###
Category: Usability
Non-Functional Requirement: The system shall allow students to complete the professor search and filtering process without requiring more than 3 navigation steps from the student dashboard.
Contributor: Mahmoud

### NFR-03 ###
Category: Reliability
Non-Functional Requirement: The system shall prevent a meeting timeslot from being booked by more than one student group at the same time.
Contributor: Mahmoud

### NFR-04 ###
Category: Availability
Non-Functional Requirement: The system should be accessible 24 hours a day, 7 days a week, except during scheduled maintenance.
Contributor: Mahmoud

### NFR-05 ###
Category: Maintainability
Non-Functional Requirement: The system shall use a modular structure that allows individual features, such as professor search, meeting scheduling, and availability management, to be modified without requiring changes to unrelated features.
Contributor: Mahmoud

Contributor: Deema

### NFR-09 ###

Non-Functional Requirement: The system shall save confirmed meeting information so that it remains available after the user logs out and then logs back in.

## Khaled Contributions ##

Category: Security
Non-Functional Requirement: The system would only allow authorized professors to be able to accept student groups assigned to their account.
Contributor: Khaled

### NFR-15 ###
Category: Reliability
Non-Functional Requirement: The system will prevent a professor from being assigned to more than 4 Senior Design teams at the same time.

## Karim Contributions ##
