## Software process model ##
Our team selected the Incremental Software Process Model for the development of our project. This model is appropriate because our project is being developed from an initial idea rather than from a completely fixed and detailed set of requirements. As we receive feedback from students and professors, some requirements may change or be refined throughout the development process.

The incremental model allows us to divide the website into smaller, manageable increments, with each increment focusing on a specific set of features. For example, the first increment could include professor profiles and areas of expertise, while later increments could introduce team-slot availability, project proposal submissions, meeting scheduling, chat, professor dashboards, and notifications. Each increment will produce a working part of the system that can be tested and reviewed before moving on to the next set of features. This approach allows us to identify problems early and improve the system based on user feedback.

However, the incremental model also has some drawbacks. One major drawback is that it requires careful planning to divide the system into suitable increments. Some features, such as chat, meeting scheduling, and notifications, may depend on components developed in earlier increments, such as user accounts, professor profiles, and databases. Poor planning could therefore lead to integration problems or require previously completed features to be modified.

Another drawback is that repeatedly developing, testing, integrating, and reviewing each increment can increase the overall time and management overhead. In addition, requirements may continue to change after each review, which could result in scope creep and potentially delay the project.

To minimize these drawbacks, our team will define the main project scope and prioritize essential requirements before development begins. We will establish a clear sequence of increments based on feature dependencies while maintaining a consistent system architecture and database design throughout development. Each increment will also be tested and integrated before the next one begins. Furthermore, we will document important changes and only accept new features when they are achievable within the project's available time and resources.
