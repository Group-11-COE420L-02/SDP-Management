# Selected Use Cases – Sequence Diagrams

## Senior Design Advisor Management System

The following use cases were selected for sequence diagram development. Each use case demonstrates interactions between system actors and objects, including request processing, validation, and status updates.

## UC-02 – Schedule Advisor Meeting

**Use Case ID:** UC-02  
**Use Case Name:** Schedule Advisor Meeting  
**Primary Actor:** Student  
**Purpose:** Allows students to select an available timeslot and submit a meeting request to a professor.  
**Reason for Selection:** Demonstrates interactions between the student and system, including checking availability, creating requests, and handling unavailable timeslots.

## UC-04 – Review Meeting Request

**Use Case ID:** UC-04  
**Use Case Name:** Review Meeting Request  
**Primary Actor:** Professor  
**Purpose:** Allows professors to review, accept, or decline meeting requests submitted by students.  
**Reason for Selection:** Demonstrates decision-making, request status updates, and notifications using conditional messages.

## UC-12 – Accept Student Group

**Use Case ID:** UC-12  
**Use Case Name:** Accept Student Group  
**Primary Actor:** Professor  
**Purpose:** Allows professors to accept student groups as their Senior Design advisees based on available capacity.  
**Reason for Selection:** Demonstrates capacity validation, advisor assignment updates, and conditional interactions when accepting student groups.

## UC-17 – Confirm Team Assignment

**Use Case ID:** UC-17  
**Use Case Name:** Confirm Team Assignment  
**Primary Actor:** Senior Design Coordinator  
**Purpose:** Allows the coordinator to verify and confirm that a student group is correctly assigned to a professor.  
**Reason for Selection:** Demonstrates interactions between multiple system objects, assignment validation, and confirmation status updates.
